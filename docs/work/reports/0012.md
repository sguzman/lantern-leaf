# Goal 0012 implementation report

## Result

Goal 0012 is complete on `codex/0012-pretty-presentation-controls-and-inline-images`.
The native egui reader now has a separate Presentation settings surface, live native rendering semantics, layered per-book persistence/reset behavior, and inline EPUB image rendering with bounded off-render-thread preparation and decode.

## Presentation controls and persistence

- Added a bounded, discoverable Presentation section separate from TTS controls.
- Wired family, weight, font size, line spacing, horizontal/vertical margins, word spacing, letter spacing, day/night highlights, pretty base scale, paragraph/block spacing, heading scales, and media limits into the existing `ReaderSettingsPatch` and `BookReaderOverrides` layering.
- Registered supported font-family/weight aliases during startup so changing family/weight selects actual native egui font faces without render-frame discovery or file I/O.
- Added `Use app presentation defaults`, which clears only presentation overrides and restores the app presentation defaults; TTS/backend/voice fields remain intact.
- Added a core regression proving presentation patches persist at book scope and reset without changing TTS backend settings.

## Pretty rendering and canonical identity

- Pretty block construction and source-to-target alignment now run on a bounded worker queue; the egui frame only consumes ready results and requests repaint.
- Margins, line spacing, word spacing, letter spacing, font family/weight, base scale, paragraph/block spacing, heading scales, and media limits affect rendering.
- Existing source-born canonical sentence IDs, ranges, highlight, follow, text-only behavior, rich inline styles, and bounded active-window rendering remain preserved.
- Added aspect-ratio/max-size regression coverage.

## EPUB/native image provenance

- Image records now retain raw references, normalized EPUB paths, chapter index, source order, extracted path, aliases, and optional alt text.
- Relative, nested, percent-encoded, fragment/query-bearing, and case/path-normalized references resolve through the EPUB extraction root only; process-current-directory and arbitrary `PathBuf::exists()` fallback are not used.
- Unresolved/corrupt images remain visible as bounded alt/source placeholders and emit concise diagnostics.
- Added a valid generated EPUB fixture with two spine chapters, PNG and encoded-space JPEG assets, nested directories, relative references, inline text around images, alt text, duplicate occurrence ordering, extraction-root containment, and 1x1 PNG/JPEG dimension assertions.

## Lazy image pipeline

- Image file reads and decoding remain in a single worker with a bounded request queue.
- Successful textures use bounded LRU-style eviction; transient failures use a five-second negative cache.
- The render thread performs only nonblocking ready-result consumption and egui texture upload, then requests repaint.
- No image decoding occurs at book open or for all images in a document.
