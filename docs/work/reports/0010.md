## Result

Implemented the Caliberate catalog cover contract and lazy catalog presentation without changing the withdrawn 42866 materialization interpretation. The worker inspected the live Caliberate API first: it exposed `has_cover` metadata but no cover bytes or stable cover endpoint. A minimal sibling-repository contract was added and pushed at `sguzman/caliberate` commit `97a41b0` on branch `codex/0010-cover-endpoint`.

LanternLeaf now carries `has_cover` through the Caliberate/catalog/app contracts, uses only the explicit Caliberate route `/api/v1/books/{id}/cover`, and keeps legacy thumbnail routes limited to the legacy Calibre provider. Caliberate catalog loading does not prefetch remote covers or materialize EPUBs. Visible catalog rows schedule at most four cover requests; request, disk, and image decoding work stays in the effect/thumbnail workers. Successful thumbnails are cached, while provider failures remain retryable in memory and are never written as permanent negative cache entries.

The starter catalog now distinguishes loading, no advertised cover, provider-unavailable, and cover-unavailable states. Provider errors are surfaced with a provider-specific bridge error and the library remains recoverable through refresh/retry. Existing local sidecar, embedded EPUB, Recents, and legacy Calibre paths remain intact.
