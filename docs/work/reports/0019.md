# Goal 0019 — Native PDF visual stability — A7

## Result

A7 corrected the rejected A6 idle-service liveness defect while preserving the accepted A1-A6 architecture and behavior. The single native `PdfNativeService` owner now returns from its raster wait after each wake/timeout and re-enters top-level metadata arbitration. A metadata request submitted after the service is idle is therefore serviced without a raster request.

The PDF container precheck now performs bounded header/tail validation rather than reading the entire file. Native Pdfium remains the authoritative parse/page-count/raster path, serialized on the one service worker. Visual PDF open remains independent of Quack-check, OCR, transcript recovery, and Python work. Detached effect panic terminalization remains intact.

## A7 implementation

- Fixed idle metadata liveness by breaking the inner raster wait after one bounded wait and rechecking metadata at the outer arbitration point.
- Preserved metadata priority over raster work and the single native Pdfium owner.
- Replaced the O(file-size) precheck with a 5-byte header plus bounded 64 KiB tail check.
- Strengthened the production lifecycle regression with deliberate idle delays before the first metadata request and before the second metadata request: `start -> idle -> metadata -> raster -> idle -> metadata`.
- The lifecycle assertion verifies valid two-page metadata, header-only failure, page-1 raster success, and identical native worker-thread identity for both metadata and raster ownership.
