# Goal 0019 — Native PDF visual stability

## Terminal result

Goal 0019 completed on the worker branch `codex/0019-native-pdf-visual-stability`.

The PDF reader now presents a native Pdfium-rasterized page in the Rust/eframe Reader shell. Pdfium initialization, PDF loading, page rasterization, decoding, and the renderer-owned CPU cache run on one bounded worker thread. The egui thread only derives requests, accepts fresh results, uploads bounded textures, and composes controls and the scrollable page surface.

## Implementation

- Added a bounded single-owner `PdfRenderWorker` with an eight-request channel and coalescing pending-key set.
- Expanded render identity to source path, document generation, page, and bounded requested width/height.
- Added stale source/generation rejection so source switches and zoom changes cannot replace the current page texture.
- Added bounded current-plus-overscan page scheduling and bounded resident egui textures.
- Added native page controls for previous/next, zoom out/reset/in, page identity, and a scrollable aspect-preserving surface.
- Added readable bounded loading/error states; failures terminalize the owned request and remain recoverable.
- Preserved the existing PDF viewport planning/eviction contracts and existing text-only fallback.
