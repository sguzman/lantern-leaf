# Goal 0019 — Native PDF visual stability — A2

## Result

A2 preserves the accepted A1 native Pdfium worker and stale-safe identity while correcting the three director-blocking defects.

The PDF reader remains native Rust/eframe/egui. Pdfium initialization, PDF open/load, rasterization, bitmap conversion, and renderer CPU caching stay on the dedicated worker. The egui thread only computes bounded requests, receives results, uploads textures, and composes the page.

## A2 corrections

- Presentation size is now separate from raster resolution. The displayed page width is `viewport width × zoom`, capped at a sane presentation bound, so zoom-in produces real scrollable overflow instead of being shrunk back to the viewport.
- Raster widths are quantized and bounded independently of presentation size; the render key still includes source, generation, page, and requested dimensions.
- Resident textures now have deterministic touch order, viewport keep ownership, and a pinned current-page key. Irrelevant/non-keep pages are evicted before nearby/current pages; the current page is never selected for eviction.
- The FIFO request channel is replaced by a bounded coalescing scheduler. A new current request purges obsolete queued work and is selected ahead of nearby work; duplicate keys coalesce, while the Pdfium worker remains single-owner.
- Added deterministic tests for portrait and landscape aspect-preserving presentation, real zoom size change, quantized/bounded raster width, navigation key ownership, terminal request recovery after failure, pinned current-page eviction, duplicate coalescing, and stale-queue current priority.
