# Goal 0019 — Native PDF visual stability — A4

## Result

A4 completed the visual-first PDF open correction on the existing native Pdfium/egui implementation. A readable local or materialized PDF now establishes a render-only degraded session without invoking Quack-check, Python, Docling, OCR, or transcript recovery. Native Pdfium still owns page rendering on its bounded worker; accepted A1/A2/A3 zoom, scheduler, stale-result, residency, and off-render-thread work was preserved.

Transcript recovery is represented as deferred/degraded state and remains subordinate to visual open. Truly missing or invalid PDF input still fails source open.

## A4 correction

- PDF source ingestion now validates readability/header and returns a render-only `SourceContent` with `PdfGeometryMode::RenderOnlyNoSync`, `PdfSyncStrategy::RenderOnly`, and an explicit non-TTS/non-sync runtime policy instead of entering the Quack-check pipeline.
- The egui open path emits bounded deferred/complete PDF recovery diagnostics while allowing `SourceOpened` and `PrettyKind::Pdf` ownership to complete.
- Added deterministic source/session tests for unavailable recovery, local/materialized convergence, render-only degraded policy, and real missing/invalid PDF failures.
- QA preparation now stages the repo-owned `scripts/quack-check` resources beside the staged config for future Gate 4 recovery use.
