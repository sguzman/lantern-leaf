# Goal 0019 — Native PDF visual stability — A3

## Result

A3 completed the director correction on the existing native Pdfium/egui implementation. The legacy arbitrary `HashMap::keys().next()` texture pre-eviction was removed. Production texture capacity is now enforced only through the viewport-aware deterministic residency path, which pins the current visible render key and evicts irrelevant entries first. Accepted A1/A2 native rendering, presentation zoom, scheduler priority, stale-result safety, bounded worker, and off-render-thread guarantees were preserved.

The bounded `pdf_render_errors` diagnostic retention remains separate from visible texture ownership.

## A3 correction

- Added `resident_texture_evictions_for_surface()`, the same production-facing helper used by `Reader::render_pdf_surface()` to construct residency entries and apply the deterministic capacity policy.
- Added a production-style over-capacity regression that inserts more than eight resident textures, including the current key, runs that helper, and verifies the current key remains while irrelevant entries are removed.
- Removed the arbitrary texture pre-eviction loop; no `pdf_textures.keys().next()` or independent `pdf_textures.len() >` capacity path remains.
