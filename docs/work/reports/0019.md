# Goal 0019 — Native PDF visual stability — A5

## Result

A5 completed the native PDF page-domain correction while preserving the accepted A1/A2/A3 renderer and A4 visual-first work. Native Pdfium now probes and validates PDF metadata during the off-UI-thread source-open effect. The resulting page count is stored as explicit PDF session state and owns PDF snapshot totals, navigation bounds, bookmarks, and renderer planning; empty transcript pagination remains separate and does not manufacture visual pages.

Header-only/parse-invalid PDFs are rejected by native open rather than being treated as healthy visual documents. Valid visual-only PDFs retain empty transcript/TTS state and still open without Quack-check, Python, Docling, OCR, or transcript recovery.

## A5 correction

- Added explicit native PDF page-count ownership to `ReaderSession`, with truthful snapshot totals and Next/Prev/SetPage bounds.
- Preserved PDF bookmark pages while metadata is pending, then clamps them against the authoritative native count.
- Probed page count through bundled Pdfium before publishing `SourceOpened`; the probe remains outside the egui/render thread.
- Added a deterministic valid two-page native PDF probe and a header-only rejection test.
- Preserved A4 render-only degraded policy and all A1/A2/A3 scheduler, stale-result, zoom, and residency behavior.
