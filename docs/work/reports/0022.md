# Goal 0022 — native PDF embedded text / TTS

## Result — A6 correction complete

This report continues the same Goal 0022 branch/report lineage. A3–A5’s accepted direction is preserved while the A6 director blockers are corrected:

- Trusted native text now promotes the canonical PDF session from render-only to full canonical text/search/TTS capability while retaining disabled exact visual sentence synchronization until geometry exists.
- Cache lookup, validation, and cache parsing now run on a detached worker. Cache hits and extraction misses re-enter the same stale-safe trusted preparation/adoption path.
- The enrichment worker now prepares only an immutable shared `Arc<PreparedPdfEmbeddedText>` document. It never clones a live `ReaderSession` or builds a reader snapshot from stale mutable state.
- The live egui commit atomically swaps the shared document into the current session, preserves current page/settings/playback/search state, and publishes a bounded current-live projection. It does not return a document-wide canonical vector, and an old document handle is dropped from a detached thread.
- Document-scale canonical sentences, page counts, search matches, and sentence-anchor projections are shared through the immutable prepared document handle; runtime projections clone only the current page and share document arcs.
- Full-text PDF search uses the complete canonical sentence domain and prepared page/local provenance, so Next/Previous navigates the owning native page without repagination or geometry ownership changes.
- Native metadata/text request submission uses `try_send` with detached retry dispatchers, so a saturated bounded queue cannot block the UI caller.
- Any queued raster request, including Nearby, is serviced through the normal Current-over-Nearby scheduler before another background text chunk.
- Text extraction uses bounded eight-page native document chunks, materially reducing document opens while preserving frequent raster arbitration.
- The trusted prepared document is now authoritative for every enriched-PDF global sentence identity, including page navigation, bookmarks, playback IDs, first-sample boundaries, and final-document exhaustion.
- Trusted adoption automatically reconciles the current live search query on a detached worker, with source/generation/query-revision stale safety for unchanged, changed, and cleared queries.
- Runtime snapshots retain a top-level trusted-document handle, and both snapshot/session retirement defer document-scale payload destruction to detached threads.
- Enrichment publication now calls the named `snapshot_enriched_pdf_bounded` projection explicitly.

## Preserved architecture

- Native Rust + eframe/egui + one process-wide Pdfium owner.
- Visual PDF open remains independent of enrichment.
- Quack-check, Python, Docling, OCR, scripts/quack-check, and external recovery remain outside this goal’s production path.
- Native text remains conservative, source/generation stale-safe, trusted-only, page aligned, cache-versioned, and connected to the existing canonical ReaderSession/TTS machinery.
- Goal 0019/0020 continuous rendering, zoom, scheduling, residency, and EPUB/TTS behavior remain covered by the repository tests.
