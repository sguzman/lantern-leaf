## Director code diagnosis

The source dependency has a concrete cause in `ReaderSession`.

`current_sentences(normalizer)` currently returns the transient TTS plan's `audio_sentences` whenever text-only is active and `text_only_show_original_text` is false. `current_highlight_idx()` similarly switches to `highlighted_audio_idx`.

That means the document UI is coupled to a bounded synthesis normalization window:

`canonical document -> TTS normalization/chunking -> audio_sentences -> visible text-only rows`

This is backwards. Text-only is a document presentation and must exist independently of whether TTS has a plan, how many audio chunks normalization creates, or whether a backend failed.

The correct ownership is:

`canonical/display document sentences -> text-only rows`

and separately:

`canonical/display sentence IDs -> normalization -> zero/one/many audio items`

The audio branch may never determine whether text exists on screen.

## A3 required correction

The reopened goal in `docs/work/ready/0009-tts-playback-polish-and-layered-voice-configuration.md` is authoritative. Key gates:

1. one text-only row per canonical/display sentence;
2. no `audio_sentences` as presentation source;
